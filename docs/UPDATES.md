# Releases and updates

The public update endpoint is `https://api.github.com/repos/mochimilk/jellyflower/releases/latest`. GitHub's [latest release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) excludes drafts and prereleases. No server, account, API token, or paid hosting is needed on users' computers.

The menu checks only when requested. It immediately shows `checking...`, keeping its settings responsive. It then shows `up to date`, `available`, `no release yet`, or `try again`. When an update is available, choosing the row again opens its installer download in the default browser. Run that installer to update. Nothing is silently downloaded or executed. The installer keeps saved preferences, updates login startup and the Start menu shortcut, and leaves older pinned helper files available until Explorer exits.

The checker uses Windows WinHTTP with normal TLS certificate validation, system proxy settings, timeouts, a 1 MiB response limit, and a total read deadline. It compares numeric `vMAJOR.MINOR.PATCH` stable versions. It offers only a nonempty uploaded `jellyflower-setup-x64.exe` or `jellyflower-setup-ARM64.exe` from the exact repository/release URL. Unexpected tags, foreign URLs, previews, missing architecture assets, malformed JSON, network failures, and API rate limits do not launch anything. Checks run on a worker that owns no window/controller pointer; closing the app does not wait on the network.

For the first release, build with `Build.ps1` and run `Publish.ps1` from normal PowerShell with GitHub CLI signed in as mochimilk. It creates a public jellyflower repository if missing, pushes the source, and publishes the matching local x64 installer and any supplied ZIP/checksum files. It does not change the visibility of an existing private repository or force-push history. Windows Credential Manager credentials are kept in their normal store.

For later releases, change the CMake version and app manifest version together, update docs/RELEASE.md, commit, then push a matching `vMAJOR.MINOR.PATCH` tag. The GitHub Actions workflow builds both architectures and creates a release only after both builds and the x64 update checks pass. Keep asset names stable: `jellyflower-setup-x64.exe` and `jellyflower-setup-ARM64.exe`. Source archives are supplied by GitHub for every release. Checksums identify downloads; they are not a substitute for Authenticode signing. The current binaries are unsigned.

Release automation uses the repository's standard `GITHUB_TOKEN` with contents write permission. No personal token is embedded in the app or repository. GitHub API requests disclose the user's IP address and the app/version user-agent to GitHub. There is no periodic check, analytics, or other app network traffic.
