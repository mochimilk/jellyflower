# Start menu acrylic

## Research and approach

[Ramen Software's Windows 11 Start menu styling guide](https://github.com/ramensoftware/windows-11-start-menu-styling-guide#custom-acrylic-background) identifies Border#AcrylicBorder as the outer Start material. Its [TranslucentStartMenu theme](https://github.com/ramensoftware/windows-11-start-menu-styling-guide/tree/main/Themes/TranslucentStartMenu) also collapses Border#AcrylicOverlay and changes border styling. Both classic and redesigned Windows 11 layouts use these names. The [Windows 11 Start Menu Styler source](https://github.com/ramensoftware/windhawk-mods/blob/main/mods/windows-11-start-menu-styler.wh.cpp) targets StartMenuExperienceHost.exe and connects to XAML diagnostics. These are primary implementation sources reviewed on 2026-10-11. Jellyflower independently implements small surface and search-header adapters, without bundling Windhawk, its general styling engine or theme/layout rules.

Microsoft documents [InitializeXamlDiagnosticsEx](https://learn.microsoft.com/en-us/windows/win32/api/xamlom/nf-xamlom-initializexamldiagnosticsex) for connecting a TAP to another XAML process. Jellyflower locates the current session's Start host at its expected Windows SystemApps path, initializes diagnostics on a background thread, and receives elements on their owning UI thread. It never launches, terminates or replaces Start. A separate jellyflower-start-v12.dll keeps this independent of Explorer's taskbar helper and fast initial taskbar path.

Only named AcrylicBorder/AcrylicOverlay elements with a StartDocked or StartMenu ancestor are accepted. Version 0.16.6 replaces the overly opaque HostBackdrop AcrylicBrush with a small XamlCompositionBrushBase: CreateBackdropBrush feeds a 25-DIP Gaussian blur, then a color matrix alpha-blends one neutral tint at 184/255. This avoids AcrylicBrush's extra luminosity layer and foreground/deactivation fallback. The native popup and Start share the tint/stroke colors; their blur kernels are different. The outer stroke is light #D2D2D2 or dark #454545, with a 1-DIP border and 20-DIP radius. AcrylicOverlay is temporarily collapsed. The material recipe is unchanged in 0.16.8. Start follows the always-acrylic jellyflower menu.

The search adapter accepts only native StartMenu/StartDocked SearchBoxToggleButton classes with the recognized template parts and MainContent ancestor. It clears the inset fill/outline and stock glyph/underline, keeps the lowercase search placeholder and native typography/behavior, and adds the exact Lucide magnifier on a non-interactive 20-DIP canvas. A one-DIP divider spans the persistent header. The magnifier uses the section's primary brush; the placeholder remains secondary. Its horizontal anchor is the shared 32-DIP header inset, never a home heading's position: Windows retains offscreen heading transforms during Show all navigation.

Version 0.16.12 uses shared spacing tokens in src/start_metrics.hpp: 32-DIP section/header inset, 12-DIP native row inner padding (20-DIP row background inset), 16-DIP grid gaps, 28-DIP section heading top margin, and 64-DIP pinned targets with 12-DIP row gaps. These are spacing/icon/target values, not fixed menu or content widths. AllAppsGrid, PinnedList and RecommendedList derive their widths/column slots from the current MainContent and scroll viewport. Native layout-slot coordinates compensate recognized parent insets without treating page navigation render transforms as padding. Recommended's React boundary receives a concrete width calculated from the current host, avoiding Yoga/NaN sizing feedback. List and expanded Recommended rows fill the content width. Grid/category slots divide the available width evenly; category backgrounds, captions and two-by-two inner targets follow the resulting card width. Fixed widths inside data-template roots are removed as well as outer container constraints. The pinned page indicator retains its own native column within the right inset. Recycled/replaced templates trigger a coalesced deferred update; unchanged geometry does not continually schedule resizing.

Pinned app and collapsed-folder captions are hidden only in their recognized native tile templates. The model text, native automation identities/tooltips, click/drag behavior and folder titles/rename fields remain. Icons center horizontally and vertically in their targets. Missing automation names/tooltips are filled from the native caption while the adapter is active and restore on exit. Folder modal panel geometry and unknown templates remain under native Windows control. All owned width/height, margin/alignment, category mini-grid, caption visibility and identity overrides retain original unset/local/bound values and restore on exit or controller loss. Names/templates were checked against read-only live build 26200 XAML diagnostics; private shell variations still need desktop acceptance checks.


The compositor graph uses the public IGraphicsEffectD2D1Interop ABI, without a Win2D runtime dependency. Microsoft documents [composition effects and XAML brushes](https://learn.microsoft.com/en-us/windows/apps/develop/composition/composition-effects). Ramen Software's current TranslucentStartMenu implementation also uses a custom backdrop blur instead of AcrylicBrush. The v12 helper waits for pinned v1/v2/v3/v4/v5/v6/v7/v8/v9/v10/v11 helpers to restore their surfaces, search and spacing adapters before connecting, so an in-app upgrade can apply without forcibly restarting Start.

Original local values, unset properties and bindings are restored on graceful exit. Property callbacks reapply after shell changes while retaining the latest original values. A duplicated SYNCHRONIZE-only controller process handle detects loss without relying on PID reuse; a one-second UI-thread timer restores after controller loss. Disabled transparency and high contrast restore the stock surface. A later controller can reuse an inactive pinned helper. The shared state and DLL name have a separate version from the Explorer bridge.

## Acceptance checks

1. Open Start before and after launching jellyflower on stock Windows 11. Compare its outer background and thin border against jellyflower's menu in both themes, using detailed wallpaper and a contrasting window behind it. Verify live blur visually; successful API calls alone do not prove visible blur.
2. Inspect Diagnose.ps1: startAttached=1, startSurfaces greater than zero, startLastResult=0 indicate connection/property success, not GPU verification. startSearchHeaders greater than zero indicates a recognized/restyled search header. Two surfaces and one header were discovered on development build 26200.
3. Check the borderless search header, lowercase search, Lucide magnifier aligned with Pinned/content, and full-width thin divider below. Search hover/focus must not restore the rounded outline or stock icon. Click search and type from Start, then use Escape/Tab and pinned/apps/power/profile controls; native behavior and animations must remain. Try both classic and redesigned Start where available, 100/125/150/175/200% DPI and multiple displays. Unsupported search layouts should remain stock.
4. Change system light/dark while Start is open. Check tint/border update, stock text contrast, and no residual opaque overlay. Disable Transparency effects or enable a contrast theme: Start must revert to stock. Restore those settings and confirm styling resumes.
5. Choose general > exit while Start is open, then reopen Start. Its original brush, overlay, border, radius, search placeholder/artwork/outline and positioning must return. Relaunch jellyflower and repeat. Force-end the controller to check restoration within about one second of Start's UI thread running. Restart StartMenuExperienceHost using normal Windows recovery tools only for a deliberate recovery test; verify automatic reconnection.
6. Update/uninstall jellyflower and check restoration and relaunch. Do not forcibly unload a pinned DLL. Keep old version files until Start and Explorer have released them. Test battery saver, Remote Desktop, graphics-driver changes and a Windows cumulative update.

## Limits

Microsoft's [acrylic guidance](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic) describes solid fallbacks under system/compositor policy. Jellyflower does not bypass them. Jellyflower restores stock styling when transparency is disabled or high contrast is enabled. Driver, remote-session and compositor restrictions can still affect backdrop rendering. Start and our native popup use different XAML/DWM blur algorithms, so shared colors and opacity inputs do not establish an exact pixel match. Start's 1-DIP XAML border can differ from DWM's physical-pixel stroke at fractional scaling. The host's own shadow remains, with its named Border radius matched to 20 DIP. MainContent's own background uses a matching 19-DIP inner radius. Existing XAML/compositor clips are left untouched: replacing the shell's handout visual Clip conflicts with its native layout/animation pipeline. Background/shadow radii restore on exit; arbitrary child visuals are not forcibly clipped.

Shell element names and layouts are private, version-dependent details. Missing elements or connection errors leave Start stock and do not disable the taskbar app. Styling tools targeting the same properties can compete. Start can suspend while hidden, delaying queued changes/restoration until its UI thread runs again. Tests cover property restoration and controlled live XAML compositor response; real Start visual parity, every shell build, suspended-host timing, alternate Start implementations and ARM64 remain desktop acceptance checks.

## Recommended replacement views and editable Search (0.16.13)

React can announce a replacement RecommendedList before its ancestor chain is connected. Recognized names remain pending until the native Start context exists. Later template events and the existing owner-liveness tick retry adoption, once per live view identity. Remove notifications discard pending entries. Responsive cells clear their wrapper MinWidth/MaxWidth constraints and fixed inner roots; compact Recommended retains columns and expanded Recommended retains full-width rows. No periodic geometry writes occur once layout is stable.

The separate SearchHost connection accepts only the current session's executable at the expected Windows SystemApps path. Its known Cortana RichSearchBoxControl/RichComposerBoxControl template must include a native SearchTextBox, placeholder and editable ScrollContentPresenter under TaskbarSearchPage. The LayerBorder viewport determines symmetric 32-DIP header insets. The native textbox's left padding becomes 28 DIP (20-DIP icon plus 8-DIP gap); template bindings move the text, caret and placeholder together. Text/document content, selection, control templates, typography and WebView results are never replaced or read. The separate TaskbarSearchBackground and input BorderElement lose their pill fill/outline. Non-interactive overlays add only the shared Lucide artwork and one-DIP divider. The native primary text brush supplies the glyph color. Placeholder changes use its native editor source, preserving template bindings. Missing/changed templates stay native.

Search runs in an AppContainer. Only the helper DLL receives its verified package SID's read/execute rights; folder ACLs, Windows security settings and user files are untouched. [InitializeXamlDiagnosticsEx](https://learn.microsoft.com/en-us/windows/win32/api/xamlom/nf-xamlom-initializexamldiagnosticsex) carries initialization data retrieved through [IXamlDiagnostics::GetInitializationData](https://learn.microsoft.com/en-us/windows/win32/api/xamlom/nf-xamlom-ixamldiagnostics-getinitializationdata). A duplicated read/write state mapping and SYNCHRONIZE-only controller handle avoid opening desktop named objects from the sandbox. A shared helper owner consumes each transferred lifetime handle once across UI threads, supports controller rebinding, and restores on graceful or abrupt owner loss. No user query is serialized, logged or sent elsewhere. A suspended host delays attachment/restoration until its UI thread resumes.

Run SearchInput for native TextBox selection/events, untouched typography/templates, resize/light/dark, padded LayerBorder geometry, separate pill clearing, retemplating and full restoration. Run StartConnection normally and with --search for native host discovery, connection, graceful exit, controller replacement and abrupt loss. Search must be open through normal user interaction for visible-template checks; the test does not launch Search or simulate typing. Private Windows revisions, all display scales and ARM64 still need desktop acceptance checks.


## Reopening header layout and Search frame (0.16.14)

The Start header is inside the native virtualized AllAppsGrid's ItemsPresenter. After styling shrinks pinned content, a stale header measurement can remain until the next scroll. StartHeader requests a coalesced, one-shot remeasure of the header branch through ItemsPresenter on attachment, SizeChanged/Loaded and return from the offscreen Start animation. It does not call UpdateLayout reentrantly, change the scroll offset, or continuously invalidate idle layouts. Native LayoutUpdated and the existing helper owner-liveness refresh observe the header against its XAML root bounds. Render transforms are used only to detect an offscreen-to-onscreen transition, never to compute layout margins. Only that transition queues a refresh; there is no new polling timer. Callbacks and queued work are removed on disable/exit.

SearchHost's AppBorder/AccentAppBorder, dropshadow and HCBorder use the shared 20-DIP surface radius; LayerBorder/AccentLayerBorder use 19 DIP to account for the inset stroke. Existing compositor clips remain Windows-owned. QueryFormulationRoot gets a separate 12-DIP top margin so the web-hosted filter tabs sit below, rather than against, the search divider. The native result host still determines its responsive size, input and rendering. These overrides retain and restore latest native values/bindings.
