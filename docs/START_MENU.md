# Start menu acrylic

## Research and approach

[Ramen Software's Windows 11 Start menu styling guide](https://github.com/ramensoftware/windows-11-start-menu-styling-guide#custom-acrylic-background) identifies Border#AcrylicBorder as the outer Start material. Its [TranslucentStartMenu theme](https://github.com/ramensoftware/windows-11-start-menu-styling-guide/tree/main/Themes/TranslucentStartMenu) also collapses Border#AcrylicOverlay and changes border styling. Both classic and redesigned Windows 11 layouts use these names. The [Windows 11 Start Menu Styler source](https://github.com/ramensoftware/windhawk-mods/blob/main/mods/windows-11-start-menu-styler.wh.cpp) targets StartMenuExperienceHost.exe and connects to XAML diagnostics. These are primary implementation sources reviewed on 2026-10-11. Jellyflower independently implements only the small outer-surface adapter, without bundling Windhawk, its general styling engine or theme/layout rules.

Microsoft documents [InitializeXamlDiagnosticsEx](https://learn.microsoft.com/en-us/windows/win32/api/xamlom/nf-xamlom-initializexamldiagnosticsex) for connecting a TAP to another XAML process. Jellyflower locates the current session's Start host at its expected Windows SystemApps path, initializes diagnostics on a background thread, and receives elements on their owning UI thread. It never launches, terminates or replaces Start. A separate jellyflower-start-v1.dll keeps this independent of Explorer's taskbar helper and fast initial taskbar path.

Only named AcrylicBorder/AcrylicOverlay elements with a StartDocked or StartMenu ancestor are accepted. A HostBackdrop AcrylicBrush receives the native popup's neutral light/dark tint color and 184/255 tint and luminosity input. The outer stroke shares the popup's color (light #D2D2D2; dark #454545), with a 1-DIP border and 8-DIP radius. The stock opaque overlay is temporarily collapsed. No font, item, size, layout, content, Start search panel, or animation is modified. The taskbar acrylic selector affects the taskbar; Start follows the always-acrylic jellyflower menu.

Original local values, unset properties and bindings are restored on graceful exit. Property callbacks reapply after shell changes while retaining the latest original values. A process handle plus controller epoch detects loss/PID reuse; a one-second UI-thread timer restores after controller loss. Disabled transparency and high contrast restore the stock surface. A later controller can reuse an inactive pinned helper. The shared state and DLL name have a separate version from the Explorer bridge.

## Acceptance checks

1. Open Start before and after launching jellyflower on stock Windows 11. Compare its outer background and thin border against jellyflower's menu in both themes, using detailed wallpaper and a contrasting window behind it. Verify live blur visually; successful API calls alone do not prove visible blur.
2. Inspect Diagnose.ps1: startAttached=1, startSurfaces greater than zero, startLastResult=0 indicate connection/property success, not GPU verification. Two surfaces (background and overlay) were discovered on the development build 26200.
3. Use Start's search, pinned apps, all apps, power/profile controls, mouse and keyboard navigation. Its normal behavior, layout and animations must remain. Try both classic and redesigned Start where available, 100/125/150/175/200% DPI and multiple displays.
4. Change system light/dark while Start is open. Check tint/border update, stock text contrast, and no residual opaque overlay. Disable Transparency effects or enable a contrast theme: Start must revert to stock. Restore those settings and confirm styling resumes.
5. Choose general > exit while Start is open, then reopen Start. Its original brush, overlay, border and radius must return. Relaunch jellyflower and repeat. Force-end the controller to check restoration within about one second of Start's UI thread running. Restart StartMenuExperienceHost using normal Windows recovery tools only for a deliberate recovery test; verify automatic reconnection.
6. Update/uninstall jellyflower and check restoration and relaunch. Do not forcibly unload a pinned DLL. Keep old version files until Start and Explorer have released them. Test battery saver, Remote Desktop, graphics-driver changes and a Windows cumulative update.

## Limits

Microsoft's [acrylic guidance](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic) describes solid fallbacks under system/compositor policy. Jellyflower does not bypass them. HostBackdrop is appropriate for Start's foreground flyout; deactivation may fall back. Start and our native popup use different XAML/DWM blur algorithms, so shared colors and opacity inputs do not establish an exact pixel match. Start's 1-DIP XAML border can differ from DWM's physical-pixel stroke at fractional scaling. The host's own shadow remains.

Shell element names and layouts are private, version-dependent details. Missing elements or connection errors leave Start stock and do not disable the taskbar app. Styling tools targeting the same properties can compete. Start can suspend while hidden, delaying queued changes/restoration until its UI thread runs again. Tests cover property/connection behavior; perceived blur, every shell build, suspended-host timing, alternate Start implementations and ARM64 remain desktop acceptance checks.
