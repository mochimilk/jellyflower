# Start menu acrylic

## Research and approach

[Ramen Software's Windows 11 Start menu styling guide](https://github.com/ramensoftware/windows-11-start-menu-styling-guide#custom-acrylic-background) identifies Border#AcrylicBorder as the outer Start material. Its [TranslucentStartMenu theme](https://github.com/ramensoftware/windows-11-start-menu-styling-guide/tree/main/Themes/TranslucentStartMenu) also collapses Border#AcrylicOverlay and changes border styling. Both classic and redesigned Windows 11 layouts use these names. The [Windows 11 Start Menu Styler source](https://github.com/ramensoftware/windhawk-mods/blob/main/mods/windows-11-start-menu-styler.wh.cpp) targets StartMenuExperienceHost.exe and connects to XAML diagnostics. These are primary implementation sources reviewed on 2026-10-11. Jellyflower independently implements small surface and search-header adapters, without bundling Windhawk, its general styling engine or theme/layout rules.

Microsoft documents [InitializeXamlDiagnosticsEx](https://learn.microsoft.com/en-us/windows/win32/api/xamlom/nf-xamlom-initializexamldiagnosticsex) for connecting a TAP to another XAML process. Jellyflower locates the current session's Start host at its expected Windows SystemApps path, initializes diagnostics on a background thread, and receives elements on their owning UI thread. It never launches, terminates or replaces Start. A separate jellyflower-start-v4.dll keeps this independent of Explorer's taskbar helper and fast initial taskbar path.

Only named AcrylicBorder/AcrylicOverlay elements with a StartDocked or StartMenu ancestor are accepted. Version 0.16.6 replaces the overly opaque HostBackdrop AcrylicBrush with a small XamlCompositionBrushBase: CreateBackdropBrush feeds a 25-DIP Gaussian blur, then a color matrix alpha-blends one neutral tint at 184/255. This avoids AcrylicBrush's extra luminosity layer and foreground/deactivation fallback. The native popup and Start share the tint/stroke colors; their blur kernels are different. The outer stroke is light #D2D2D2 or dark #454545, with a 1-DIP border and 20-DIP radius. AcrylicOverlay is temporarily collapsed. The material recipe is unchanged in 0.16.8. Start follows the always-acrylic jellyflower menu.

The 0.16.8 search adapter accepts only the native StartMenu/StartDocked SearchBoxToggleButton classes with a recognized Grid template, BorderElement, PlaceholderText, ContentPresenter and MainContent ancestor. It clears the inset input fill/outline, hides stock image/glyph variants and underline, changes the visible/accessibility label to lowercase search, and adds the exact supplied Lucide path/circle on a non-interactive 24-DIP canvas. A 1-DIP divider spans MainContent below the header. The icon follows PinnedListHeaderText when available; the compact layout uses a 24-DIP content inset when that named heading is absent. The native template, font, foreground, tab stop, event handlers, button hitbox and focus behavior remain. Only the content/caret horizontal transforms change, preserving any native transform. In 0.16.10, named section headings move from 63 to 24 DIP. Recognized app ItemsWrapGrid and footer containers reduce their 52-DIP left/right margins to 12 DIP, retaining their native internal padding. Right-side action buttons use the same reduced margin; the native header grid uses 24 DIP on both sides. Top/bottom margins, layout measurement, hit targets, scrolling, templates, fonts and host animation remain native. Only the closest known AllAppsGrid/PinnedList owns an app-wrap margin override; unrelated/folder lists are excluded. Margin callbacks compact the latest shell values while preserving vertical changes. Unknown layouts retain their native spacing. Unknown/older layouts lacking these required parts keep stock search; recognized acrylic surfaces can still work. The control names are documented in the styling guide above and were checked against a read-only XAML tree probe on build 26200.

The compositor graph uses the public IGraphicsEffectD2D1Interop ABI, without a Win2D runtime dependency. Microsoft documents [composition effects and XAML brushes](https://learn.microsoft.com/en-us/windows/apps/develop/composition/composition-effects). Ramen Software's current TranslucentStartMenu implementation also uses a custom backdrop blur instead of AcrylicBrush. The v4 helper waits for pinned v1/v2/v3 helpers to restore their surfaces, and v3 search adapters, before connecting, so an in-app upgrade can apply without forcibly restarting Start.

Original local values, unset properties and bindings are restored on graceful exit. Property callbacks reapply after shell changes while retaining the latest original values. A process handle plus controller epoch detects loss/PID reuse; a one-second UI-thread timer restores after controller loss. Disabled transparency and high contrast restore the stock surface. A later controller can reuse an inactive pinned helper. The shared state and DLL name have a separate version from the Explorer bridge.

## Acceptance checks

1. Open Start before and after launching jellyflower on stock Windows 11. Compare its outer background and thin border against jellyflower's menu in both themes, using detailed wallpaper and a contrasting window behind it. Verify live blur visually; successful API calls alone do not prove visible blur.
2. Inspect Diagnose.ps1: startAttached=1, startSurfaces greater than zero, startLastResult=0 indicate connection/property success, not GPU verification. startSearchHeaders greater than zero indicates a recognized/restyled search header. Two surfaces and one header were discovered on development build 26200.
3. Check the borderless search header, lowercase search, Lucide magnifier aligned with Pinned/content, and full-width thin divider below. Search hover/focus must not restore the rounded outline or stock icon. Click search and type from Start, then use Escape/Tab and pinned/apps/power/profile controls; native behavior and animations must remain. Try both classic and redesigned Start where available, 100/125/150/175/200% DPI and multiple displays. Unsupported search layouts should remain stock.
4. Change system light/dark while Start is open. Check tint/border update, stock text contrast, and no residual opaque overlay. Disable Transparency effects or enable a contrast theme: Start must revert to stock. Restore those settings and confirm styling resumes.
5. Choose general > exit while Start is open, then reopen Start. Its original brush, overlay, border, radius, search placeholder/artwork/outline and positioning must return. Relaunch jellyflower and repeat. Force-end the controller to check restoration within about one second of Start's UI thread running. Restart StartMenuExperienceHost using normal Windows recovery tools only for a deliberate recovery test; verify automatic reconnection.
6. Update/uninstall jellyflower and check restoration and relaunch. Do not forcibly unload a pinned DLL. Keep old version files until Start and Explorer have released them. Test battery saver, Remote Desktop, graphics-driver changes and a Windows cumulative update.

## Limits

Microsoft's [acrylic guidance](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic) describes solid fallbacks under system/compositor policy. Jellyflower does not bypass them. Jellyflower restores stock styling when transparency is disabled or high contrast is enabled. Driver, remote-session and compositor restrictions can still affect backdrop rendering. Start and our native popup use different XAML/DWM blur algorithms, so shared colors and opacity inputs do not establish an exact pixel match. Start's 1-DIP XAML border can differ from DWM's physical-pixel stroke at fractional scaling. The host's own shadow remains.

Shell element names and layouts are private, version-dependent details. Missing elements or connection errors leave Start stock and do not disable the taskbar app. Styling tools targeting the same properties can compete. Start can suspend while hidden, delaying queued changes/restoration until its UI thread runs again. Tests cover property restoration and controlled live XAML compositor response; real Start visual parity, every shell build, suspended-host timing, alternate Start implementations and ARM64 remain desktop acceptance checks.

## Compact padding and larger corners (0.16.10)

Run StartSpacing for native XAML heading/app/footer/right-button layout, unknown-list rejection, latest vertical changes and local/unset/binding/destructor restoration. StartSurface verifies the 20-DIP radius and unchanged compositor tint recipe. StartSearch verifies native typography/search behavior plus header alignment/divider rendering. On the desktop, compare both sides in pinned-expanded/collapsed, list/category, scrolling, companion-open/closed, light/dark and multiple DPI layouts; confirm the scrollbar, footer buttons and search remain usable. Diagnose reports startSpacingOverrides alongside surfaces/searches. Exit and simulate controller loss to verify all margins and corner values return to Windows defaults. Private Windows layouts can change; unknown anchors are skipped.
